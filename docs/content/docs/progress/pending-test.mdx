# 待测试

- Windows 本地视频合并下载诊断：选择多个已生成视频并开始合并时，片段应按顺序读取并在读取阶段显示进度；任一片段读取失败时，应明确显示对应的片段序号。若浏览器无法连接本地媒体服务，应显示本地服务地址，而不是只显示 `Failed to fetch`。

- Seedance 渠道协议：在渠道编辑器中应可选择 `Seedance` 协议，新建该协议渠道时默认接口地址为 `https://ark.cn-beijing.volces.com/api/v3`，也可填写 `http://127.0.0.1:3001` 这类实现同协议透传的中转裸地址；程序应按 Seedance 协议自动补 `/api/v3`，最终调用 `/api/v3/contents/generations/tasks`，不得错误补成 `/v1/contents/generations/tasks`。请求包含 `content`、`ratio`、`resolution`、`duration`、`generate_audio` 和 `watermark`；普通视频配置的“生成声音”开关应映射到 `generate_audio`，视频反推创建的分镜配置应固定发送 `generate_audio: false`。选择 `OpenAI` 协议时继续走 `/v1/videos` 兼容链路，不应假设支持 Seedance 原生声音字段。
- 本地 Deepgram 原片口播校准：启动 Windows 本地媒体服务后，在“反推视频分镜”中启用 Deepgram 校准，填写本地服务地址、Token 和首次使用的 Deepgram API Key。网页应把本地原视频上传到 `media-service`，由 FFmpeg 提取音轨并直接调用 Deepgram，不要求公网视频地址；反推完成后，分镜文本和视频配置应把有字词重叠的原片口播标记为“Deepgram 校准”，并使用真实字词起止时间覆盖视频理解模型估算。Deepgram Key 应只保存到本机媒体服务配置，不写入画布节点；Deepgram 未配置、鉴权失败、无音轨或网络失败时，视频反推仍应创建分镜并明确提示已保留“模型估算”。
- 豆包语音合成：渠道编辑器中的 `seed-tts-2.0` 音频模型应可选择“OpenAI 兼容”或“V3 时间戳”模式。OpenAI 模式继续请求 `/v1/audio/speech`，并在请求体 `voice` 中发送所选火山引擎 `Voice_type`（如 `zh_female_vv_uranus_bigtts`），不得再发送 `alloy`；V3 模式应请求当前渠道的 `/api/v3/tts/unidirectional`，通过 `X-Api-Key` 发送 New API Token、通过 `X-Api-Resource-Id` 发送模型名，并固定发送 `enable_subtitle: true`。响应为 `text/plain; charset=utf-8` 和 chunked NDJSON 时，应合并音频 Base64 分片并把 `sentence.words` 保存为毫秒级 `audioTimeline`；生成完成后音频节点应出现“字词时间轴”入口，可查看完整旁白、每个字词的开始/结束时间、置信度和“已应用 N/M 个视频分镜”，未匹配分镜应列出序号和原因。重新生成时应覆盖旧时间轴，未收到完成标记、API Key 无效、音色与资源不匹配或接口返回错误码时应明确失败。视频反推创建的“音频生成配置”应只发送一份上游“台词与旁白”，连续重试不得累积提示词或生成超长循环音频；同一反推任务生成 TTS 后，应按各分镜 `narrationText` 自动回写视频配置的旁白区间、匹配状态和 4-15 秒生成时长；任一分镜缺少旁白文本或无法按顺序匹配时不得写入错误时间轴，视频配置应持久显示失败原因，不得修改其他反推任务的节点。
- 批量生成分镜配置：反推分镜后，在左侧“画布元素”进入选择模式并勾选多个视频配置节点，点击“批量生成”应并发触发每个配置各自生成，成功/失败数量应有明确提示；已在生成中的配置不应被重复触发。
- 统一旁白时间轴：视频反推生成的分镜视频配置应默认关闭“生成声音”，使用“台词与旁白 → 音频生成配置”一次生成固定 TTS 音频。在左侧画布元素选择至少两个按顺序排列的视频和一个生成完成的音频节点后点击“合并视频”，弹窗应显示统一旁白；存在 V3 字词时间戳时，应按视频节点的 `narrationText` 顺序确定镜头区间且不调用停顿分析，任一分镜匹配失败或没有有效时间戳时才整次回退本地停顿分析。画面过长应裁剪、过短应保持末帧补齐，最终成片应只使用统一旁白音轨。完成后画布应创建“完整成片”和“成片时间轴”节点，时间轴包含每个镜头的精确开始/结束时间、字幕文本和硬切位置；旁白文本缺失、段数不匹配、选择多个音频、分析失败和取消任务时应显示明确错误且不写入半成品。
- Windows 本地视频合并：在 `media-service/` 安装依赖并运行 `npm run dev`，确认控制台显示 Local URL、Connect token 和可用 FFmpeg；在画布左侧“画布元素”进入选择模式，选中至少两个已有内容的视频后点击“合并视频”，填写本地服务地址和 Token。片段应按画布从上到下、同一行从左到右显示和上传；火山 TOS 等跨域远程视频应由本地媒体服务代理下载，不再出现浏览器 `Failed to fetch`。服务端应逐段统一为 1080×1920、30fps、H.264 8Mbps、AAC 48kHz 双声道 192kbps，再按顺序拼接；已有音轨必须保留，无音轨片段应自动补静音音轨。前端选择数量与服务收到数量必须一致，不一致时应报错且不生成缺段成片。进度应持续更新，完成后画布应创建“完整成片”视频节点并连接所有源视频；合并中切换画布或点击停止后不得在其他画布写入成片。Token错误、本地服务未启动、FFmpeg缺失、片段读取失败和手动停止应显示明确错误。运行 `npm run package:win` 后，`media-service/release/windows-x64/` 应包含 `InfiniteCanvasMedia.exe`、`ffmpeg.exe` 和使用说明，目标机器无需 Codex。
- Seedance OpenAI 兼容中转：只有选择 `OpenAI` 协议的自定义中转渠道中的 Seedance 模型才以 JSON 请求 `POST /v1/videos`，请求体包含 `model`、`prompt`、限制在 4-15 秒的 `duration`、`width`、`height`、`fps: 30`、`n: 1` 和 `response_format: "url"`；返回 `task_id` 后应与其他异步视频任务一样每 30 秒查询一次 `GET /v1/videos/{task_id}`，在 `metadata.url` 出现后下载视频并创建可播放的画布视频节点。`queued`、`in_progress` 状态应继续轮询，失败状态或任务完成但 URL 为空时应显示明确错误。选择 `Seedance` 协议的官方或中转地址统一使用 `/api/v3/contents/generations/tasks` 原生任务接口。
- 豆包长视频流式分析：使用豆包系列视频理解模型反推较长视频时，请求应携带 `stream: true`、`max_tokens: 16384` 并持续读取 SSE 内容；中转站响应为标准流式 Chat Completions 时，前端不应再因等待数分钟而显示 `Network Error`，最终仍应解析完整 JSON 并创建分镜节点。渠道返回普通 JSON 时也应正常解析；模型以 `finish_reason: length` 结束、接口错误、空响应和手动取消时应显示明确提示。
- 长视频反推分镜：为渠道模型配置“视频理解”能力和调用脚本后，视频节点工具栏应出现“反推分镜”；上传整段视频并提交分析后，应同时分析画面和原始音轨，存在可辨识人声的镜头必须返回台词/旁白及原片口播开始、结束时间。应创建视频概要、改写文案、标题话题、台词/旁白音频配置，以及按时间顺序排列的分镜文本节点和视频生成配置节点；分镜文本显示原片口播区间，视频配置持续显示原片镜头、原片口播、新 TTS 旁白、实际剪辑时长、模型生成时长和对齐状态。不足 4 秒的相邻镜头应优先合并并保留完整口播范围，超过 15 秒的镜头拆分后口播区间不得超出子镜头；视频配置生成时长应被限制在 4-15 秒。旧分镜需重新反推才能获得原片口播字段；模型返回非 JSON、视频读取失败、取消分析时应显示明确错误且不创建半成品节点。首版不包含自动剪辑和一键发布。

- 多能力模型脚本：同一个渠道模型可分别配置“调用脚本”和“视频理解脚本”；配置视频理解脚本后，该文本模型应同时出现在文本模型和视频理解模型选择器中，普通文本生成继续使用“调用脚本”，反推分镜使用“视频理解脚本”。

- 豆包原生视频分析：选择名称包含 `doubao` 的视频理解模型时，应自动通过自定义渠道地址的 `/v1/chat/completions` 请求，即使此前保存过其他视频理解脚本也应优先使用豆包协议；请求体使用 `video_url.url = data:video/mp4;base64,...`、默认 `fps: 0.3` 和分镜提示词。模型返回有效 `shots` 后应创建完整分镜节点；请求体超过 64 MB、视频超过 50 MB、渠道不支持豆包视频协议或模型未返回文本时，应显示接口响应详情和明确错误。

- 网站统计：确认部署配置中不再支持百度统计，页面不会请求 `hm.baidu.com`；未配置 GA4 时不加载统计脚本，配置 `ANALYTICS_GA4_ID` 后仍可正常上报页面浏览。

- 对外品牌名称：确认首页、浏览器标题和顶部导航显示为 `new-canvas`，并确认 README 保留原项目归属说明。

- 提示词来源：6 个内置来源应从 Image Prompts 统一仓库读取，更新后数量依次为 323、494、53、76、126、129；提示词仍按 6 个来源分组并可独立启用，来源内可继续按 `tags` 筛选。添加标准 JSON URL 后应能查看内容，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 我的提示词：在提示词中心切换到「我的提示词」，验证新增、编辑、删除和搜索；从提示词库保存后应出现在个人列表、画布左侧提示词面板和提示词选择弹窗中，刷新页面后数据仍保留在本地，Agent 搜索提示词时也应能查到。
- 画布提示词库：不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；关闭当前页面后应回退到最近聚焦且仍连接的页面，其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示向下箭头且新消息不强制打断阅读，点击箭头后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧以主题浅底气泡显示，AI 回复应在左侧保留 Agent 图标并使用开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
